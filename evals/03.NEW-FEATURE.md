# Évaluation — Nouvelle feature : EcoTrip Calculator

## Consignes

> Durée : 3h · En groupes

L’**EcoTrip Calculator** existe déjà et gère plusieurs modes de transport. Vous devez y **ajouter le support de l’avion** en utilisant :

- La **Sprout Class** : le nouveau comportement est écrit dans une classe séparée, testée en isolation, puis branchée dans le code existant
- Le **TDD** : chaque comportement est piloté par un test rouge avant d’écrire le code

> Vous ne touchez au code existant **qu’en dernière étape**, pour brancher la nouvelle classe.
> Les tests existants doivent rester au vert tout au long de l’exercice.

**Livrable :** le code versionné avec des commits atomiques (un cycle red-green-refactor par commit).

# Calculer l'impact d'un trajet en avion
## Formule mathématique

```
CO₂eq (kg) = Distance (km) × EF(distance) × Multiplicateur_Classe × FRI
```

| Paramètre               | Définition                                  | Valeur                  |
|-------------------------|---------------------------------------------|-------------------------|
| `EF(distance)`          | Facteur d'émission selon la portée          | voir tableau ci-dessous |
| `Multiplicateur_Classe` | Espace cabine relatif à l'économique        | voir tableau ci-dessous |
| `FRI`                   | Forçage Radiatif (traînées de condensation) | **2.0**                 |

**Facteurs d'émission par portée**

| Portée         | Distance         | EF (kgCO₂eq/km/pax) |
|----------------|------------------|---------------------|
| Court-courrier | < 1 000 km       | **0.258**           |
| Moyen-courrier | 1 000 – 3 499 km | **0.187**           |
| Long-courrier  | ≥ 3 500 km       | **0.152**           |

> Rationale : le décollage et l'atterrissage consomment proportionnellement plus sur les courts trajets.

**Multiplicateurs de classe**

| Classe          | Multiplicateur |
|-----------------|----------------|
| Economy         | 1.0            |
| Premium Economy | 1.6            |
| Business        | 2.5            |
| First           | 4.0            |

**Exemples de calcul :**
- 300 km, Economy : `300 × 0.258 × 1.0 × 2.0 = **154.8 kgCO₂eq**`
- 5 000 km, Business : `5000 × 0.152 × 2.5 × 2.0 = **3 800 kgCO₂eq**`
- 5 000 km, Economy : `5000 × 0.152 × 1.0 × 2.0 = **1 520 kgCO₂eq**`

## User Story

**En tant qu'** utilisateur souhaitant mesurer l'impact de mes déplacements aériens,
**je veux** calculer l'empreinte carbone d'un vol en renseignant la distance et la classe,
**afin de** comparer mes options et prendre des décisions de voyage plus éclairées.

## Critères d'acceptation

**Portées et facteurs d'émission**

- Un vol < 1 000 km utilise EF = 0.258 kgCO₂eq/km
- Un vol entre 1 000 et 3 499 km utilise EF = 0.187 kgCO₂eq/km
- Un vol ≥ 3 500 km utilise EF = 0.152 kgCO₂eq/km

**Multiplicateurs de classe**

- Economy = ×1.0, Premium Economy = ×1.6, Business = ×2.5, First = ×4.0

**Forçage radiatif**

- Le FRI de 2.0 est toujours appliqué (non configurable par l'utilisateur)

**Précision du résultat**

- Le résultat est arrondi à 1 décimale en kgCO₂eq

**Valeurs invalides**

- Une distance ≤ 0 retourne une erreur explicite
- Une classe non reconnue retourne une erreur explicite

**Affichage**

- Le résultat affiche : valeur, unité (kgCO₂eq)

## Barème — 20 points

### Sprout Class (6 pts)

| Critère                                                                                          | Points |
|--------------------------------------------------------------------------------------------------|--------|
| Le nouveau comportement avion est **isolé** (non ajouté directement dans le code existant)       | 3 pts  |
| La classe sproutée est **testée indépendamment** du reste du système                             | 2 pts  |
| L'intégration dans le code existant est **minimale et localisée** (un seul point de branchement) | 1 pt   |

### TDD (8 pts)

| Critère                                                                | Points |
|------------------------------------------------------------------------|--------|
| Les **cas nominaux** sont couverts (au moins une portée + une classe)  | 2 pts  |
| Les **frontières de portée** sont testées (999/1000 km, 3499/3500 km)  | 2 pts  |
| Les **valeurs invalides** sont testées (distance ≤ 0, classe inconnue) | 2 pts  |
| Les commits montrent des **cycles red-green-refactor** identifiables   | 2 pts  |

### Qualité du code produit (4 pts)

| Critère                                                                                         | Points |
|-------------------------------------------------------------------------------------------------|--------|
| Le code est **lisible** : les noms expriment l'intention métier (portée, classe cabine, FRI...) | 2 pts  |
| Les **tests existants passent toujours** après intégration                                      | 2 pts  |

### Ce qui sera pénalisé

- Comportement avion ajouté **directement dans le code existant** sans Sprout → critère Sprout = 0
- Tests en échec ou supprimés → −2 pts
- Commits "big bang" sans cycles red-green visibles → critère TDD cycles = 0
- Valeurs magiques non nommées dans le code de calcul → −1 pt
